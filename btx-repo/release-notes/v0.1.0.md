## 1. Summary

v0.1.0 delivers the foundational federated trust fabric for Bharat Trust Exchange (BTX). This release establishes the complete architectural baseline: three production-grade microservices (consent lifecycle, trust node registry, federation sync), a cloud-agnostic adapter layer (AWS/GCP/Azure), a policy-as-code engine, tamper-evident audit trail, and a signed release pipeline. The codebase is deployment-ready for India-only Phase 1 with real cloud credentials and successful cloud conformance certification.

---

## 2. Highlights

- **Consent lifecycle management** — Citizens can grant, query, and revoke consent; revocation cascades to all registered peer trust nodes within the 1500ms ADR-0020 SLA
- **Federated architecture** — Trust nodes sync via Merkle-root-verified state machine; no central coordinator required
- **Cloud-agnostic adapters** — AWS, GCP, and Azure KMS + object store, with stub for local dev; no cloud SDK in service code
- **DPDP 2023 compliance posture** — Threat model and DPIA complete; data residency enforced at startup (ADR-0025); citizen rights (access, erasure, portability) documented
- **Signed, attested releases** — GitHub Actions pipeline produces SBOMs (Syft), Cosign-signed images, SLSA L3 attestations, and a signed evidence pack
- **25 cloud conformance tests** — AWS runner implemented; GCP/Azure runners ready for cloud credentials
- **Audit trail integrity** — Transactional outbox (ADR-0021) + Merkle root chain; INSERT-only audit_events with WORM Kafka topic

## 4. Service Changes

### control-plane (v0.1.0)
- `POST /v1/consents` — grant consent with policy eval, transactional audit, outbox
- `POST /v1/consents/:id/revoke` — revoke with cascade option
- `GET /v1/consents/:id` — query with principal auth check
- `GET /v1/consents/:id/audit` — immutable audit trail
- `GET /healthz` — DB + Kafka health
- OutboxPublisher worker — drains audit events to Kafka (idempotent)
- Daily Merkle root computation

### registry (v0.1.0)
- `POST /v1/nodes` — register / upsert trust node
- `GET /v1/nodes/:id` — lookup + heartbeat update
- `GET /v1/nodes` — list active nodes with status filter
- `GET /healthz`

### trust-node (v0.1.0)
- `POST /v1/federation/sync` — peer sync with Merkle root verification
- `GET /v1/federation/state/:id` — get or initialise federation state
- `GET /v1/federation/pending` — list pending peer syncs
- `GET /healthz`

## 5. Policy Changes

- Policy bundle structure established: `policy/consent/`, `policy/registry/`, `policy/federation/`
- OBL-RESIDENCY-CHECK: blocks cross-border federation sync until ADR-0025 expansion gate
- OBL-MINOR-GUARDIAN: blocks consent grant for minors without guardian consent flag
- OBL-CONSENT-FULL / OBL-CONSENT-STATUS-ONLY: response shape minimisation per caller role
- All policy decisions fail-closed (PDP error → deny)

## 7. Security

- No CVEs addressed (first release; dependency audit clean at release time)
- mTLS + SPIFFE SVID injection points present on all cross-service paths

## 15. Upgrade & Rollback

### First deployment (no prior version)
```bash
# 1. Provision cloud infrastructure (Terraform/OpenTofu)
cd infra/ && tofu apply -var-file=envs/staging.tfvars

# 2. Configure cloud provider
export CLOUD_PROVIDER=aws
export AWS_REGION=ap-south-1
export AWS_KMS_SIGNING_KEY_ARN=<arn>
export AWS_S3_BUCKET=<bucket>

# 3. Run DB migrations
psql $CONTROL_PLANE_DB_URL -f services/control-plane/migrations/001_init_consents.sql
psql $REGISTRY_DB_URL -f services/registry/migrations/001_init_nodes.sql
psql $TRUST_NODE_DB_URL -f services/trust-node/migrations/001_init_federation.sql

# 4. Deploy via ArgoCD
kubectl apply -f k8s/

# 5. Run cloud conformance
npm run cert:aws

# 6. Verify health
curl https://control-plane.btx.internal/healthz
curl https://registry.btx.internal/healthz
curl https://trust-node.btx.internal/healthz
```

### Rollback (if deployment fails)
```bash
# ArgoCD rollback to prior revision
argocd app rollback btx-control-plane
argocd app rollback btx-registry
argocd app rollback btx-trust-node
# DB migrations: v0.1.0 migrations are additive — no rollback needed for first deploy
```
