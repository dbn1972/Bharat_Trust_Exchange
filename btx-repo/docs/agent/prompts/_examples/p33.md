# Example for P-33

## Scenario

We discovered that `make integration` and `make certify` returned success even when no meaningful service behavior had been exercised. The implementation behind those targets relied on placeholder `ok(...)` responses and structural existence checks rather than executable release evidence.

## Wrong approach

```diff
- if (!hasPath('infra')) pending(name, 'no-infra-dir');
- ok(name, { runner: 'tfsec-placeholder' });
+ ok(name, { runner: 'tfsec', findings: parsedResults });
```

The wrong approach still treats the absence of a real scan as success-shaped output.

## Right approach

```diff
- ok(name, { mode: 'placeholder', args });
+ const report = runRealIntegrationSuite(args);
+ if (!report.pass) fail(name, 'integration-failed', report);
+ writeEvidence('evidence/release-gates/integration.json', report);
+ ok(name, { runner: 'integration-suite', evidence: report.path });
```

## Expected artefacts

- updated `Makefile` and `scripts/*.sh`
- executable `tools/*.mjs` checks with real fail paths
- `evidence/release-gates/integration.json`
- `evidence/release-gates/certify.json`
- reviewer note showing no reachable placeholder PASS path remains
