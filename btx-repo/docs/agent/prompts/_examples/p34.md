# Example for P-34

## Scenario

Phase 7 and Phase 9 tests existed but were not credible release evidence: some used Mocha/Chai outside the main Vitest path, some asserted only `expect(true)`, and some skipped behavior based only on health checks. The goal is to convert them into real hermetic end-to-end verification.

## Wrong approach

```diff
- it('should revoke consent with cascade option', async () => {
-   // Placeholder for revoke test
-   expect(true).to.be.true;
- });
+ it('revokes consent and verifies audit trail + outbox + query state', async () => {
+   const consent = await grantConsent(...);
+   const revoke = await revokeConsent(consent.id, ...);
+   expect(revoke.status).to.equal(200);
+   const audit = await getAuditTrail(consent.id);
+   expect(audit.body.some((e) => e.eventType === 'consent.revoked')).to.equal(true);
+ });
```

## Right approach

1. Start the BTX stack hermetically.
2. Register nodes through the real registry API.
3. Exercise grant/query/revoke through the real control-plane API.
4. Verify audit and federation side effects.
5. Emit machine-readable evidence under `evidence/e2e/`.

## Expected artefacts

- migrated Vitest-based integration harness
- no remaining `expect(true)` placeholders in targeted test files
- no remaining Mocha/Chai dependency for release-evidence tests
- evidence bundle with request/response traces and timing summaries
